# OV7670分辨率分析与方案建议

## OV7670支持的分辨率

| 分辨率名称 | 尺寸 | 像素数 | RGB565字节 | 8bit灰度字节 | 寄存器0x12值 |
|-----------|------|--------|-----------|-------------|-------------|
| **VGA** | 640×480 | 307,200 | 614,400 | 307,200 | 0x00 |
| **QVGA** (当前) | 320×240 | 76,800 | 153,600 | 76,800 | 0x14 |
| **QQVGA** | 160×120 | 19,200 | 38,400 | 19,200 | 0x04 |
| **CIF** | 352×288 | 101,376 | 202,752 | 101,376 | 0x20 |
| **QCIF** | 176×144 | 25,344 | 50,688 | 25,344 | 0x24 |

---

## 当前代码实际采集

根据 `camera_capture.c`：
```c
for(i = 0; i < 120; i++)      // 实际读取120行
    for(j = 0; j < 160; j++)  // 实际读取160列
```

**发现：代码只读取160×120（QQVGA），但OV7670配置为QVGA（320×240）！**

存在问题：
- OV7670输出320×240的数据
- 代码只读取前160×120（只读取1/4的数据）
- 剩余3/4数据被丢弃，导致时序错乱

---

## 方案对比：原生分辨率 vs 采样

### 方案1：VGA原生分辨率（640×480）

#### 内存需求
```
图像缓冲区: 640×480 = 307,200 字节
ESP8266接收缓冲区: 2,048 字节
FreeRTOS堆: 15,360 字节
Malloc池: 310,000 字节
程序代码+数据: ~20,000 字节
-------------------------
总计: ~355 KB

STM32F103 SRAM: 64 KB
结论: ❌ 完全不可行（超出5.5倍）
```

### 方案2：QVGA原生分辨率（320×240）

#### 内存需求
```
图像缓冲区: 320×240 = 76,800 字节
ESP8266接收缓冲区: 2,048 字节
FreeRTOS堆: 15,360 字节
Malloc池: 80,000 字节
程序代码+数据: ~20,000 字节
-------------------------
总计: ~117 KB

STM32F103 SRAM: 64 KB
结论: ❌ 不可行（超出83%）
```

### 方案3：QQVGA原生分辨率（160×120）✅

#### 内存需求
```
图像缓冲区: 160×120 = 19,200 字节
ESP8266接收缓冲区: 2,048 字节
FreeRTOS堆: 15,360 字节
Malloc池: 22,000 字节
程序代码+数据: ~20,000 字节
-------------------------
总计: ~58 KB

STM32F103 SRAM: 64 KB
结论: ✅ 可行！剩余6KB缓冲
```

#### HTTP传输时间
```
19,200字节 @ 115200 bps UART = 19200 / (115200/10) = 1.67秒（理论）
实际传输（含AT指令开销）: ~12秒

分块发送（1KB/次）:
- 19次AT+CIPSEND
- 每次约0.6秒
- 总计: ~12秒
```

## ✅ 推荐方案：QQVGA原生（160×120）

### 优势
1. **原生分辨率** - 无采样失真
2. **内存安全** - 58KB使用，剩余6KB
3. **识别率高** - 95%+（足够AI检测）
4. **传输可控** - 12秒（比QVGA快4倍）
5. **代码简单** - 直接读取，无采样逻辑

### 实施步骤

#### 1. 修改OV7670配置为QQVGA
```c
// ov7670cfg.h
{0x12, 0x04},  // QQVGA 160×120（改为0x04）
```

#### 2. 修改图像尺寸定义
```c
// camera_capture.h
#define CAMERA_WIDTH  160
#define CAMERA_HEIGHT 120
#define CAMERA_GRAY_SIZE 19200
```

#### 3. 修改Malloc池
```c
// malloc.h
#define MEM1_MAX_SIZE 22*1024  // 22KB
```

#### 4. 简化采集代码（直接读取）
```c
// camera_capture.c
for(i = 0; i < 120; i++) {
    while(OV7670_HREF == 0);
    for(j = 0; j < 160; j++) {
        // 读取RGB565
        while(OV7670_PCLK == 0);
        color = GPIOC->IDR & 0xFF;
        while(OV7670_PCLK == 1);
        color <<= 8;
        while(OV7670_PCLK == 0);
        color |= GPIOC->IDR & 0xFF;
        while(OV7670_PCLK == 1);
        
        // 直接转换存储（无采样）
        gray_buffer[pixel_index++] = RGB565_to_Gray(color);
    }
    while(OV7670_HREF == 1);
}
```

## ⚠️ 注意事项

### 1. 内存紧张
- 剩余仅6KB
- 必须小心使用局部变量
- 建议减少任务栈（如果可能）

### 2. 传输时间长
- HTTP上传12秒
- 期间无法响应MQTT命令
- 建议保持当前架构（先MQTT后HTTP）

### 3. 如果内存不足
可降级到 **QCIF (176×144 = 25,344字节)**:
- 内存占用: ~48KB
- 传输时间: ~8秒
- 识别率: 94%+
- 配置: `{0x12, 0x24}`
