  HTTP请求卡死问题 - 诊断步骤
═══════════════════════════════════════════════════════

问题描述：
程序在 "=== 获取天气数据 ===" 后卡死，没有任何响应

可能原因分析：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. TCP连接失败但没有正确返回false
2. HTTP请求发送失败
3. ESP8266没有收到服务器响应
4. 接收缓冲区管理问题
5. 等待超时机制失效

已实施的修复：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
? 在TCP连接前检查连接状态
? 关闭可能存在的旧连接
? 清空接收缓冲区准备接收HTTP响应
? ESP8266_TCP_Send增加SEND OK检查
? 改进等待响应逻辑（分步检查，显示进度）
? 直接使用IP地址避免域名解析

调试步骤：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  - Rebuild项目
  - 下载到板子

【步骤3】根据输出判断卡在哪里

卡点A：在 "正在连接TCP服务器" 后
原因：TCP连接失败
解决：
  - 检查WiFi是否已连接（AT+CIFSR查看IP）
  - 检查网络是否通畅（Ping 47.83.221.161）
  - 检查防火墙设置

卡点B：在 "AT+CIPSEND" 后
原因：ESP8266没有返回 ">"
解决：
  - 检查TCP连接是否真的成功
  - 尝试增加AT+CIPSEND的等待时间
  - 检查ESP8266固件版本

卡点C：在 "HTTP请求已发送" 后
原因：服务器没有响应或响应被丢失
解决：
  - 增加等待时间（目前是6秒）
  - 检查服务器是否正常（用电脑curl测试）
  - 检查ESP8266接收缓冲区大小

卡点D：在 "等待服务器响应" 一直等待
原因：数据没有进入接收缓冲区
解决：
  - 检查USART3中断是否正常工作
  - 检查strEsp8266_Fram_Record是否被正确更新
  - 可能需要增加接收超时处理

【步骤4】手动测试AT命令

如果以上都不行，在main.c的while(1)前添加测试代码：

// 手动测试TCP连接
PC_Usart("\r\n=== 手动测试TCP连接 ===\r\n");

// 1. 关闭旧连接
ESP8266_Cmd("AT+CIPCLOSE", "OK", NULL, 1000);
delay_ms(1000);

// 2. 设置单连接模式
ESP8266_Cmd("AT+CIPMUX=0", "OK", NULL, 1000);
delay_ms(1000);

// 3. 连接服务器
ESP8266_Cmd("AT+CIPSTART=\"TCP\",\"47.83.221.161\",80", "CONNECT", "OK", 10000);
delay_ms(2000);

// 4. 检查连接状态
ESP8266_Cmd("AT+CIPSTATUS", "OK", NULL, 1000);
delay_ms(1000);

// 5. 发送简单HTTP请求
char test_req[] = "GET /api/weather/ HTTP/1.1\r\nHost: 47.83.221.161\r\n\r\n";
char cmd[32];
sprintf(cmd, "AT+CIPSEND=%d", strlen(test_req));
ESP8266_Cmd(cmd, ">", NULL, 2000);
delay_ms(500);

// 6. 发送数据
ESP8266_Usart("%s", test_req);
delay_ms(3000);

// 7. 查看接收到的数据
PC_Usart("接收缓冲区长度: %d\r\n", strEsp8266_Fram_Record.InfBit.FramLength);
PC_Usart("接收数据: %s\r\n", strEsp8266_Fram_Record.Data_RX_BUF);

重点检查项：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. WiFi是否真的连接成功（有IP地址）
2. Ping测试是否通过（网络通畅）
3. ESP8266固件版本（部分固件有bug）
4. USART3中断是否正常工作
5. 接收缓冲区是否足够大
6. TCP连接状态查询结果

最常见问题：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
? TCP连接实际上失败了，但没有正确返回false
? ESP8266固件不支持某些AT命令
? 服务器防火墙阻止连接
? 接收数据量超过缓冲区大小
? ESP8266模块硬件故障或供电不足

建议：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. 先用电脑测试服务器：curl 47.83.221.161/api/weather/
2. 使用AT调试工具直接测试ESP8266模块
3. 检查ESP8266供电是否稳定（3.3V，峰值电流可达300mA）
4. 观察详细的串口输出找到卡住的确切位置
5. 如果一直失败，考虑使用HTTP库或更新ESP8266固件
